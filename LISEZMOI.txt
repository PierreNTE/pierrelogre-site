-----------------------------------------------------------------------

  visite guidée finie, terrier trouvé, fiche ouverte, clics LinkedIn, temps de chargement et fluidité
  par type d'appareil, provenance. Aucun cookie, aucune adresse IP, aucun identifiant gardé : pas de

  Lire les chiffres : supabase.com > projet > Table Editor > vues stats_jour, stats_entonnoir,
  stats_appareils, stats_sources (voir plus bas).
- Vrais téléphones : le test pierrelogre.com/#bench envoie maintenant ses mesures tout seul (plus

- Premier chargement plus léger : les dix régions lointaines arrivent dans un second fichier, juste
  après l'affichage du village. Au démarrage : 254 Ko compressés au lieu de 321 (−21 %). Le total
  téléchargé ne change pas ; une partie neuve démarre sans attendre, « Reprendre » attend la fin.
- Accessibilité : tout se fait au clavier (Tab parcourt le menu et les bêtises, Entrée ouvre un indice,
  flèches dans les onglets du carnet, Échap ferme les fenêtres, le focus revient où il était) ; les
  fenêtres sont annoncées correctement aux lecteurs d'écran ; contrastes des textes orange renforcés
  (norme WCAG AA, vérifiée automatiquement à chaque test). N replie le carnet (Tab ne le fait plus).

Lire la mesure d'audience (phpMyAdmin)
--------------------------------------
Espace client OVH > Hébergements > Bases de données > phpMyAdmin, puis dans la base, rubrique Vues :
- stats_jour : par jour (heure de Paris), visites, parties, visite guidée finie, terrier trouvé, fiche ouverte,
  clics LinkedIn, durée moyenne.
- stats_entonnoir : sur 30 jours, combien de visites atteignent chaque étape, de la visite au clic LinkedIn.
- stats_appareils : téléphone / tablette / ordinateur : temps de chargement (médiane), qualité graphique, fluidité.
- stats_sources : d'où viennent les visites. Astuce : dans un post LinkedIn, mets le lien
  https://pierrelogre.com/?utm_source=linkedin pour voir ces visites à part.
- Mesures des téléphones (#bench) : onglet SQL >
    SELECT at, device, props FROM events WHERE name = 'Bench' ORDER BY at DESC;
Rien de tout cela n'est lisible depuis le site : seulement depuis phpMyAdmin.

Nouveautés (5.7 : la première minute et le téléphone)
------------------------------------------------------
- La carte d'accueil s'affiche tout de suite, dans la langue du visiteur, pendant que le jeu se charge
  derrière ; un clic sur « Jouer » pendant le chargement lance la partie dès qu'elle est prête.
- Première visite : trois bêtises guidées en douceur (faire sursauter le jardinier, voler son chapeau,

- Au téléphone : joystick flottant (le pouce peut se poser n'importe où en bas à gauche), boutons en arc
  sous le pouce droit, « Attraper » qui s'allume quand un objet est à portée et devient « Poser »,
  portée un peu plus large au doigt. Partout : le renard glisse le long des murs au lieu de s'y coller.
- Écrans à 120 Hz : 60 images par seconde régulières (moins de chauffe et de batterie).
- Le jeu est plus léger à télécharger : 313 Ko compressés au lieu de 352.
- Les habitants réagissent davantage : surpris, puis agacés (poing levé), puis ils chassent le renard
  en agitant les bras ; celui qui rapporte un objet le lâche de surprise. Trois glapissements différents.
- Rythme : « Doublé ! » quand deux bêtises s'enchaînent ; si l'on tourne en rond, un indice arrive plus tôt
  (45 s) et, au village, une flèche montre où aller.

Mise en ligne (manuelle, par FileZilla)
---------------------------------------
1. Télécharge une sauvegarde de l'ancien contenu de www/, puis VIDE complètement www/.
2. Dépose tout le contenu du dossier www/ de ce zip, y compris les fichiers cachés
   .htaccess et .well-known/ (FileZilla : Serveur > Forcer l'affichage des fichiers cachés).
   HTTPS : le .htaccess envoie tout le monde vers https://pierrelogre.com et active HSTS. Il faut donc que
   le certificat SSL de l'hébergement soit actif. Le certificat Let's Encrypt gratuit inclus avec
   l'hébergement OVH suffit (espace client OVH, rubrique de l'hébergement, « Certificat SSL ») :
   les certificats payants ne sont pas utiles, pas plus que l'option « Visibilité Pro » (gestion payante
   de présence en ligne) : le site n'en dépend pas.
3. Ouvre https://pierrelogre.com en navigation privée (en anglais), https://pierrelogre.com/fr/ (en français),
   puis https://pierrelogre.com/nimporte-quoi (la page 404 du renard doit s'afficher) et
   https://pierrelogre.com/fr/mentions-legales/ (les mentions légales).
4. Retire pierrelogre.com du projet Vercel « pierre-logre » (Settings > Domains) si ce n'est pas fait.

Classement partagé (MySQL OVH)
------------------------------
Les classements sont dans la base MySQL de l'hébergement OVH (voir version 5.12).
- Les identifiants de la base sont seulement dans pierrelogre-api/config.php chez OVH (à côté de www/, jamais
  dedans). Ce fichier n'est ni dans GitHub ni envoyé par le déploiement : ne le partage avec personne.
- Retirer un pseudo : phpMyAdmin > onglet SQL > DELETE FROM scores WHERE pseudo = 'xxx';
- Si la base est indisponible, le jeu continue avec le classement du navigateur.

Mise en ligne automatique (recommandée)
--------------------------------------
Le dossier source contient le workflow GitHub Actions .github/workflows/deploy.yml : à chaque mise à jour
de la branche main, GitHub construit le site, lance tous les tests, et seulement s'ils passent, envoie le
site sur OVH en SFTP (miroir exact du dossier www/, plus le code de l'API dans pierrelogre-api/). Ce qu'il faut faire une fois :
1. Sur github.com, crée un dépôt PRIVÉ vide (sans README), par exemple « pierrelogre-site ».
2. Dans ce dépôt : Settings > Secrets and variables > Actions > New repository secret, crée :
     OVH_FTP_HOST      ftp.cluster121.hosting.ovh.net
     OVH_FTP_USER      ton identifiant FTP (espace client OVH > Hébergement > FTP-SSH)
     OVH_FTP_PASSWORD  ton mot de passe FTP
   Ces identifiants ne doivent jamais apparaître ailleurs (ni dans le code, ni dans un message).
3. Donne le nom du dépôt à Claude : il y envoie le code ; le premier déploiement part tout seul.
Ensuite, chaque modification arrive sous forme de « pull request » : un clic sur « Merge » la met en ligne.
Suivi : onglet Actions du dépôt (vert = en ligne, rouge = rien n'a été envoyé, le site reste tel quel).

Ajouter un monde plus tard
--------------------------
Chaque zone est un fichier dans src/js/regions/ (chargé après le démarrage : regions/lazy.js). Le README (dossier source) explique comment
en ajouter une (par exemple un monde spatial) : décor, personnages, bêtises, secrets, ambiance.

Sécurité du compte et du domaine (à faire une fois)
---------------------------------------------------
- Active la double authentification sur ton compte OVH.
- Mot de passe FTP long et unique ; supprime les accès FTP inutiles.
- Active DNSSEC sur le domaine.
- Garde le SPF OVH existant (v=spf1 include:mx.ovh.com -all) et ajoute :
    TXT  _dmarc.pierrelogre.com  "v=DMARC1; p=quarantine"
- Ajoute un enregistrement CAA : pierrelogre.com CAA 0 issue "letsencrypt.org"
