pierrelogre.com · le renard fait des bêtises (version 5 : le monde s'agrandit)
============================================================================

Nouveautés (5.7 : la première minute et le téléphone)
------------------------------------------------------
- La carte d'accueil s'affiche tout de suite, dans la langue du visiteur, pendant que le jeu se charge
  derrière ; un clic sur « Jouer » pendant le chargement lance la partie dès qu'elle est prête.
- Première visite : trois bêtises guidées en douceur (faire sursauter le jardinier, voler son chapeau,
  le jeter dans la fontaine), un post-it à la place du carnet, une flèche et un chevron vers la cible,
  une petite fête à la fin. « Passer » à tout moment ; vue une fois, elle ne revient plus.
- Au téléphone : joystick flottant (le pouce peut se poser n'importe où en bas à gauche), boutons en arc
  sous le pouce droit, « Attraper » qui s'allume quand un objet est à portée et devient « Poser »,
  portée un peu plus large au doigt. Partout : le renard glisse le long des murs au lieu de s'y coller.
- Écrans à 120 Hz : 60 images par seconde régulières (moins de chauffe et de batterie).

Nouveautés (5.1 : direction artistique)
---------------------------------------
- Monde beaucoup plus vivant : herbes et fleurs qui ondulent et se couchent au passage du renard,
  forêt dense avec sous-bois, ombres de nuages, papillons, lapins, hérisson, fumée des cheminées,
  montgolfière (rare), lumière et ambiance propres à chaque zone.
- Les zones encore fermées « dorment » (couleurs éteintes) ; à l'ouverture, une vague de couleur
  les réveille. Des fleurs poussent là où le renard fait ses bêtises : le monde grandit avec lui.
- Menu : qualité graphique Auto / Haute / Basse.

Mise en ligne (manuelle, par FileZilla)
---------------------------------------
1. Télécharge une sauvegarde de l'ancien contenu de www/, puis VIDE complètement www/.
2. Dépose tout le contenu du dossier www/ de ce zip, y compris les fichiers cachés
   .htaccess et .well-known/ (FileZilla : Serveur > Forcer l'affichage des fichiers cachés).
   HTTPS : le .htaccess envoie tout le monde vers https://pierrelogre.com et active HSTS. Il faut donc que
   le certificat SSL de l'hébergement soit actif. Le certificat Let's Encrypt gratuit inclus avec
   l'hébergement OVH suffit (espace client OVH, rubrique de l'hébergement, « Certificat SSL ») :
   les certificats payants ne sont pas utiles, pas plus que l'option « Visibilité Pro » (gestion payante
   de présence en ligne) : le site n'en dépend pas.
3. Ouvre https://pierrelogre.com en navigation privée, puis https://pierrelogre.com/nimporte-quoi
   (la page 404 du renard doit s'afficher).
4. Retire pierrelogre.com du projet Vercel « pierre-logre » (Settings > Domains) si ce n'est pas fait.

Classement partagé (facultatif, gratuit)
----------------------------------------
Sans rien faire, le classement du mini-jeu fonctionne déjà, mais chaque visiteur ne voit que ses
propres scores. Pour un classement commun à tous :
1. Crée un compte sur https://supabase.com puis un projet (région Europe, offre gratuite).
2. Dans le projet : SQL Editor > New query, colle le contenu de supabase/leaderboard.sql
   (dossier source), puis Run. La table « scores » est créée avec ses règles de sécurité :
   lecture et ajout seulement, pseudo et score vérifiés, anti-spam.
3. Project Settings > API : copie l'URL du projet et la clé publique « anon » (ou « publishable »).
   NE COPIE JAMAIS la clé « service_role » / « secret ».
4. Dans src/site.config.json : renseigne "leaderboard": { "supabaseUrl": "...", "anonKey": "..." }
   puis reconstruis (npm run build) ou pousse sur GitHub si le déploiement automatique est actif.
   Le build autorise ce domaine dans la CSP, et seulement lui.

Mise en ligne automatique (facultative, recommandée)
----------------------------------------------------
Le dossier source (foxsite-source.zip) contient un workflow GitHub Actions :
à chaque modification poussée sur GitHub, il construit le site, lance les tests,
puis l'envoie sur OVH en FTPS. Pour l'activer :
1. Crée un dépôt privé sur GitHub et pousse-y le contenu de foxsite-source.zip.
2. Dans le dépôt : Settings > Secrets and variables > Actions, crée :
     OVH_FTP_HOST      ftp.cluster121.hosting.ovh.net
     OVH_FTP_USER      ton identifiant FTP (espace client OVH > Hébergement > FTP-SSH)
     OVH_FTP_PASSWORD  ton mot de passe FTP
   Ces identifiants ne doivent jamais apparaître ailleurs (ni dans le code, ni dans un message).
3. Onglet Actions > « Déploiement pierrelogre.com » > Run workflow.

Ajouter un monde plus tard
--------------------------
Chaque zone est un fichier dans src/js/regions/. Le README (dossier source) explique comment
en ajouter une (par exemple un monde spatial) : décor, personnages, bêtises, secrets, ambiance.

Sécurité du compte et du domaine (à faire une fois)
---------------------------------------------------
- Active la double authentification sur ton compte OVH (et sur Supabase si tu l'utilises).
- Mot de passe FTP long et unique ; supprime les accès FTP inutiles.
- Active DNSSEC sur le domaine.
- Garde le SPF OVH existant (v=spf1 include:mx.ovh.com -all) et ajoute :
    TXT  _dmarc.pierrelogre.com  "v=DMARC1; p=quarantine"
- Ajoute un enregistrement CAA : pierrelogre.com CAA 0 issue "letsencrypt.org"
