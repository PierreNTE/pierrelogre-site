Mise en ligne (manuelle, par FileZilla)
---------------------------------------
1. Télécharge une sauvegarde de l'ancien contenu de www/, puis VIDE complètement www/.
2. Dépose tout le contenu du dossier www/ de ce zip, y compris les fichiers cachés
   .htaccess et .well-known/ (FileZilla : Serveur > Forcer l'affichage des fichiers cachés).
   HTTPS : le .htaccess envoie tout le monde vers https://pierrelogre.com et active HSTS. Il faut donc que
   le certificat SSL de l'hébergement soit actif. Le certificat Let's Encrypt gratuit inclus avec
   l'hébergement OVH suffit (espace client OVH, rubrique de l'hébergement, « Certificat SSL ») :
   les certificats payants ne sont pas utiles, pas plus que l'option « Visibilité Pro » (gestion payante
   de présence en ligne) : le site n'en dépend pas.
3. Ouvre https://pierrelogre.com en navigation privée (en anglais), https://pierrelogre.com/fr/ (en français),
   puis https://pierrelogre.com/nimporte-quoi (la page 404 du renard doit s'afficher) et
   https://pierrelogre.com/fr/mentions-legales/ (les mentions légales).
4. Retire pierrelogre.com du projet Vercel « pierre-logre » (Settings > Domains) si ce n'est pas fait.

Mise en ligne automatique (recommandée)
--------------------------------------
Le dossier source contient le workflow GitHub Actions .github/workflows/deploy.yml : à chaque mise à jour
de la branche main, GitHub construit le site, lance tous les tests, et seulement s'ils passent, envoie le
site sur OVH en FTPS (miroir exact du dossier www/). Ce qu'il faut faire une fois :
1. Sur github.com, crée un dépôt PRIVÉ vide (sans README), par exemple « pierrelogre-site ».
2. Dans ce dépôt : Settings > Secrets and variables > Actions > New repository secret, crée :
     OVH_FTP_HOST      ftp.cluster121.hosting.ovh.net
     OVH_FTP_USER      ton identifiant FTP (espace client OVH > Hébergement > FTP-SSH)
     OVH_FTP_PASSWORD  ton mot de passe FTP
   Ces identifiants ne doivent jamais apparaître ailleurs (ni dans le code, ni dans un message).
3. Donne le nom du dépôt à Claude : il y envoie le code ; le premier déploiement part tout seul.
Ensuite, chaque modification arrive sous forme de « pull request » : un clic sur « Merge » la met en ligne.
Suivi : onglet Actions du dépôt (vert = en ligne, rouge = rien n'a été envoyé, le site reste tel quel).

Ajouter un monde plus tard
--------------------------
Chaque zone est un fichier dans src/js/regions/ (chargé après le démarrage : regions/lazy.js). Le README (dossier source) explique comment
en ajouter une (par exemple un monde spatial) : décor, personnages, bêtises, secrets, ambiance.

Sécurité du compte et du domaine (à faire une fois)
---------------------------------------------------
- Active la double authentification sur ton compte OVH (et sur Supabase si tu l'utilises).
- Mot de passe FTP long et unique ; supprime les accès FTP inutiles.
- Active DNSSEC sur le domaine.
- Garde le SPF OVH existant (v=spf1 include:mx.ovh.com -all) et ajoute :
    TXT  _dmarc.pierrelogre.com  "v=DMARC1; p=quarantine"
- Ajoute un enregistrement CAA : pierrelogre.com CAA 0 issue "letsencrypt.org"
